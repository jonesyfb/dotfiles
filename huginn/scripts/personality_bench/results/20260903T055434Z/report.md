## Finding R1: repeated-identical-request metaphor dominance, improved but not eliminated

Rendering the exact same Brave scenario 10 times back-to-back still produces predator/consumption imagery (eating, hoarding, feasting, mouths, hunger) in 8/10 outputs, down from 10/10 in the baseline. The recent-style ledger (`memory.log_style`/`memory.recent_styles`, keyed by `purpose`) IS being written and read every call — verified via raw.json's ordering — and the prompt does receive a 'your last few lines leaned on these styles... vary your approach' hint. But that hint is advisory, not a hard constraint, and Brave's own facts (memory/tab count) are exactly the case the system prompt explicitly still permits hunger/hoarding for ('when resource use genuinely earns it') — so the model keeps returning to the metaphor family the prompt itself sanctions for this input, hint or no hint. This is a real, honest residual character-quality issue: the diversity work broadened the register across *different* scenario types convincingly (5 categories used across 30 outputs, including weather/omen and machinery/noise that never appeared in the baseline), but did not fully solve repetition under the harshest test (identical input, back-to-back, no other variation to draw on). A harder constraint (e.g. mechanically rejecting a flavor that repeats the immediately-prior call's category for the same purpose) would close this further but was not built in this slice — flagged as a follow-up, not silently claimed as solved.

## Finding R2 (was baseline Finding 1): protected-value fragility — fully resolved

The baseline's core problem — the model losing an exact-copying contest for numbers, IP:port strings, re-cased proper nouns, and paraphrased error text — cannot recur structurally. Protected facts (`protected_keys`) are never included in the model's prompt at all; the model only sees a note that some values are withheld. The 6 protected-value scenarios from the baseline (08, 09, 10, 11, 19, 20) all passed cleanly in this run (0 retries, 0 failures), including the exact 4 that failed in the baseline.

## Finding R3 (was baseline Finding 3): worthiness gap — resolved

Scenario 02 (normal Brave use) now correctly denies with `not worthwhile: no positive worthiness signal attached` when no signal is attached, and allows once `evaluate_periodic_worthiness()` detects a real baseline deviation — both demonstrated live in this run (see no_call_scenarios in raw.json). `random_chime_worker` now computes this signal from real parsed stats every hour instead of building an opportunity unconditionally.

## Finding R4 (was baseline Finding 4): fixed 30-minute cooldown vs. requested duration — resolved

Scenario 17 (nudge dismissed for a full hour) now uses `ambient.set_snooze()` with an explicit 3600-second duration, independent of the automatic 1800s cooldown. Verified live at both boundary points: still denied at 59:59 (`suppressed: 'procrastination_nudge' snooze active (1s remaining)`), allowed again at exactly 60:00 ([start, expiry) semantics, as specified).
